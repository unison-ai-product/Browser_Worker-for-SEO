# Money Watch 停止からの復帰（money_alert が立ったときに読む）

> **必要なときだけ読む**。このプラグインの作業（検索・記事閲覧・GSC/GA4・WP 管理画面）で金銭・契約・課金の画面に触れることは通常ない。立ったら異常事態として扱う。

## 復帰手順

1. 立った時点で**変更操作はすべて止まる**（読み取り — read_page / get_page_text / screenshot / scroll — は許可。`browser_batch` は読み取りのみでも停止中は deny されるので単体で呼ぶ）
2. 何の画面で・どの操作の直前に検知されたかを 3 行以内でユーザーに報告する（例: WP のプラグイン購入ページに遷移していた／GA4 の課金設定タブを開いていた）
3. **AI は自分の判断で `money_alert` を消さない**。ユーザーが「その操作は不要／続行してよい」と明示したときだけ `rm memory/.workflow/money_alert` し、承認の事実を session-log に 1 行記録して再開する
4. 続行不要なら該当タブを閉じて（tabs_close は変更操作扱いなので承認後）元の作業に戻る

## 検知の 2 段階

- **【弱】（`Money Watch・注意`）は停止しない** — 注意喚起だけ。操作対象が金銭・契約に触れないことを自分で確かめて進んでよい。同じ弱パターンは同じ URL では 1 回だけ出る
- **【強】（money_alert）** — 変更操作の直前に要素名・ref 等の識別子を照合して立つ。座標クリックは文字列を持たないので照合されない（画面読み取り側の検知が担う）

## 前セッションからの持ち越し

money_alert はタスクをまたいで残る（/SEO記事 の開始でも消さない）。セッション開始時に「残留フラグ」の通知が出たら、まずユーザーに「前回の金銭停止が残っています」と 1 行で伝え、指示を仰ぐ。**自分の判断で rm しない。**

## 同じ画面で【強】が繰り返し止まる場合

パターンの過検知。該当パターンと画面を 1 行で報告し、`knowledge/feedback/lessons.md` に起票して `hooks/scripts/money-watchlist.txt` の見直しで対処する（AI がリストを消したり抑制を書いたりしない）。
