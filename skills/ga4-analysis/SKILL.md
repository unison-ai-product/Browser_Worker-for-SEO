# GA4分析スキル

## 1. 安全境界（ga4-jp より）

| 操作 | 可否 |
|---|---|
| レポート・探索の閲覧とデータ取得、探索の新規作成（既存を上書きしない。名前に `-seo-worker` を付ける） | 自律可 |
| キーイベントの追加、カスタムディメンションの追加、チャネルグループの作成 | 本プラグインでは行わない（必要なら takumi-cmo ga4-jp の手順で人間と） |
| データ保持設定の変更、データフィルターの有効化、プロパティ・ストリーム削除、権限変更、広告リンク | **禁止** |
| PII を含むデータの送信・記録 | **禁止**（URL のクエリ文字列に `email` `tel` `name` 等があれば記録から落とす） |

## 2. 原則

- GA4 は**設定した分しか測れない**。無い指標は「未計測」と記録し、推測で埋めない。
- GA4 の値は**出所を分けて保持**し、GSC や自前計測の数値と足し合わせない。
- 滞在時間・スクロールは**相関の補助指標**であり因果を主張しない。
- CV は**日 × URL × ゴール**の集計だけを扱う。個人単位の行動ログは持たない。

## 3. 見る指標と読み方

| 指標 | 取り方 | 読み方 |
|---|---|---|
| ランディングページ別セッション × キーイベント率 | レポート「ランディングページ」+ キーイベント | 率が低くセッションが多い記事が CV ストーリーリライトの優先 |
| エンゲージメント率・平均エンゲージメント時間 | 同上 | 短いのに CV が無い → 冒頭の結論と CTA 位置を見直す |
| スクロール（`scroll` = 90% 到達 1 回のみ。段階計測は GTM 側） | 探索: イベント `scroll` × ページ | 90% 到達率が低い記事は中盤の離脱。段階データがあれば離脱節を特定 |
| ページパス遷移（次のページ） | 探索: 経路データ探索 | 内部リンクが機能しているか。想定外の遷移は導線の見直し |
| 流入元（参照元 / メディア） | レポート「トラフィック獲得」 | AI 系リファラ（chatgpt.com / gemini.google.com / perplexity.ai / copilot.microsoft.com 等）を LLMO の効果として別記録 |
| CV に至ったランディング → 遷移 → CV ページ | 探索: ファネル | 「勝ち記事」の導線を型として抽出（他記事へ移植する根拠） |

## 4. CV ストーリー仮説の出し方

1. 記事ごとに「読者がどの節まで読み（スクロール）、どこへ抜け（遷移）、CV したか（キーイベント）」を並べる。
2. content-marketing §3 の H2 パターン 6 型のどれに当たるかを付け、型の「着地点」と実際の離脱位置を比較する。
3. 仮説は 5 行で: 離脱している節 / CTA が遠い・近い / 内部リンクの向き / 追加すべき節 / 削るべき節。
4. リライト候補は seo.db `rewrite_candidates`（kind = cv_story）に根拠指標付きで追記。

## 5. 記録

seo.db `ga4_snapshots`（url, date_range, sessions, engaged_rate, avg_engagement_sec, scroll90_rate, key_events, key_event_rate, next_page_top, source_medium_top, captured_at）に追記型。
